## 1. Tujuan

Melengkapi `docs/backend/05.TESTING.md` untuk lapisan UI. Logika bisnis diuji di backend; frontend menguji perilaku tampilan, form, akses, dan alur pengguna.

---

## 2. Tools

| Kebutuhan | Tool | Status |
| :--- | :--- | :--- |
| Unit/komponen | Vitest + `[ISI: Testing Library]` | Vitest terpasang |
| E2E | Playwright (`e2e/`) | Terpasang |
| Aksesibilitas otomatis | `[ISI: mis. @axe-core/playwright]` | Belum |
| Visual regression | `[ISI: opsional]` | — |

Perintah: `bun run test` · `bun run test:watch` · `bun run test:coverage` · `bun run test:e2e`  
Colocate `*.test.tsx` di samping komponen. Pola AAA, nama tes deskriptif, tes independen. Jangan menjalankan tes terhadap data produksi.

---

## 3. Prioritas

| Prioritas | Cakupan |
| :--- | :--- |
| 🔴 P1 | Login/logout, proteksi rute per role, isolasi data PW/PC di UI, alur surat sampai `SENT`, form laporan (WK/Safari/Pesantren) |
| 🟡 P2 | Penanganan `ActionResult` (field error, error umum, pending), `StatusBadge`, filter/pagination via URL, upload file (validasi UI) |
| 🟢 P3 | Komponen presentasional murni, layout responsif |

---

## 4. Pengujian Komponen

Yang diuji:
- `ActionForm`/`FormField`: error per field tampil, `aria-describedby` benar, tombol disabled saat pending.
- `StatusBadge`: semua nilai enum punya varian dan teks.
- `Sidebar`: item sesuai role (data uji per kelompok role).
- `OrgFillerFields`: muncul hanya untuk `ORGANIZATIONAL`.
- `FileUpload`: menolak tipe/ukuran tidak valid dengan pesan jelas.

Mock: Server Action dan auth client di-mock; jangan memanggil database.

---

## 5. E2E (Playwright)

Perjalanan utama:

| # | Alur | Akun uji (seed) |
| :--- | :--- | :--- |
| 1 | Login → dashboard → logout | OWNER |
| 2 | Akses `/admin` sebagai role tidak berhak → diarahkan ke `/dashboard?error=unauthorized` | PC |
| 3 | Role wajib MFA tanpa MFA → dipaksa ke `/dashboard/security/mfa` | OWNER |
| 4 | Buat surat → review → approve → kirim (nomor muncul hanya setelah `SENT`) | ADMIN_SEKRETARIAT |
| 5 | PC melihat daftar surat — hanya data organisasinya | PC |
| 6 | Input laporan mingguan WK dengan `namaPengisi` & `jabatanPengisi` | akun organisasi |
| 7 | Form publik permohonan guru bantu → status `DIAJUKAN` | tanpa login |
| 8 | Verifikasi surat via QR (halaman publik) | tanpa login |

Jalankan alur P1 (nomor 1, 4, 6, 7) pada viewport mobile 360×800 dan desktop 1280×800 (`projects` di `playwright.config.ts`); tambah tablet 768×1024 untuk halaman dashboard.

Akun uji berasal dari `prisma/seed.ts` (`owner@…`, `sekretariat@…`, `pw.jatim@…`, `pc.surabaya@…`). Gunakan database test terpisah; jangan memakai kredensial dari dokumentasi di lingkungan produksi.

## 6. Checklist Halaman

Setiap halaman baru:

- [ ] State loading, kosong, error, dan sukses tersedia
- [ ] Role tanpa izin tidak melihat menu/tombol dan ditolak server
- [ ] Form: error per field, pending, cegah submit ganda
- [ ] Responsif di 360, 768, 1280, 1920px: tanpa scroll horizontal halaman, sidebar → drawer, tabel → kartu, aksi form sticky di mobile
- [ ] Navigasi keyboard + fokus terlihat; kontras AA
- [ ] Hanya token desain (tanpa hex/spacing mentah)
- [ ] Animasi menghormati `prefers-reduced-motion`
- [ ] Tidak ada `any` dan `console.log`

---

## 7. Definition of Done (UI)

- Halaman/komponen tercatat di `03.INFORMATION_ARCHITECTURE.md` / `04.COMPONENTS.md`
- Tes P1/P2 yang relevan ditulis dan lulus
- `bun run lint` dan `bun run typecheck` lulus
- Keputusan arsitektur UI baru dicatat di ADR
- Dokumen `docs/frontend/` terkait diperbarui

---

## 8. Larangan Keras

- ❌ DILARANG tes yang bergantung pada data produksi.
- ❌ DILARANG meng-skip tes P1 untuk mengejar rilis.
- ❌ DILARANG tes UI yang menguji implementasi (class CSS) alih-alih perilaku.
- ❌ DILARANG menaruh kredensial nyata di kode tes.
