## 1. Tujuan

Mengatur cara UI memanggil Server Action dan query, serta menampilkan hasilnya secara konsisten. Kontrak sisi server ada di `docs/backend/03.API_CONVENTIONS.md`.

---

## 2. Alur Mutasi dari Sisi UI

```text
Form (Client) → Server Action → [Zod → Auth → RBAC → Logic → DB → revalidate] → ActionResult → UI
```

- Mutasi internal HANYA lewat Server Action, bukan `fetch('/api/...')`.
- Validasi Zod di client boleh untuk UX cepat (skema dipakai ulang dari `modules/*/domain`), tetapi **tidak menggantikan** validasi server.
- Setelah sukses, server memanggil `revalidatePath`/`revalidateTag`; UI cukup menampilkan hasil dan (bila perlu) `router.push`.

---

## 3. Menangani ActionResult

Kontrak (`types/api.ts`):

```ts
type ActionResult<T> = {
  success: boolean
  data?: T
  error?: string                     // pesan umum
  errors?: Record<string, string[]>  // error per field (Zod flatten)
}
```

Pola form (usulan):

```tsx
'use client'

import { useActionState } from 'react'
import { submitLetter } from '@/modules/letter/presentation/actions/create-letter.action'
import type { ActionResult } from '@/types/api'

const initial: ActionResult<unknown> = { success: false }

export function LetterForm() {
  const [state, formAction, pending] = useActionState(
    async (_prev: ActionResult<unknown>, formData: FormData) => submitLetter(formData),
    initial,
  )

  return (
    <form action={formAction}>
      {/* FormField per input, tampilkan state.errors?.perihal */}
      {state.error && <p role="alert">{state.error}</p>}
      <button type="submit" disabled={pending}>Simpan</button>
    </form>
  )
}
```

Aturan tampilan:

| Hasil | Perilaku UI |
| :--- | :--- |
| `errors` (per field) | Pesan di bawah field terkait, fokus ke field pertama yang salah |
| `error` umum | Banner/alert di atas form (`role="alert"`) |
| `Unauthorized` | Arahkan ke `/login?callbackUrl=...` |
| `Forbidden` | Pesan akses ditolak; jangan bocorkan alasan internal |
| `success` | Toast singkat + navigasi/refresh sesuai konteks |
| Pending | Tombol disabled + label "Menyimpan…" (cegah submit ganda) |

Server Action tidak melempar error ke client — selalu baca `success`.

## 4. Pengambilan Data

- Data untuk tampilan diambil di **Server Component** lewat `modules/<domain>/presentation/queries/*.query.ts`.
- Jangan mengambil data awal lewat `useEffect` + `fetch`.
- Data yang jarang berubah memakai Cache Components (`'use cache'`, `cacheLife`, `cacheTag`) — tag mengikuti tabel di `03.API_CONVENTIONS.md` §8.3.
- Query selalu men-scope data sesuai organisasi pemanggil (di server). UI tidak melakukan penyaringan keamanan.

## 5. State di URL: Pagination, Filter, Sort

Gunakan `searchParams` sebagai sumber kebenaran agar bisa dibagikan dan di-refresh.

| Param | Default | Maks | Contoh |
| :--- | :--- | :--- | :--- |
| `page` | 1 | — | `?page=2` |
| `limit` | 20 | 100 | `?limit=50` |
| `q` | — | — | `?q=surat tugas` |
| `status` | — | — | `?status=SENT` atau `SENT,APPROVED` |
| `from` / `to` | — | — | `?from=2026-01-01&to=2026-11-15` |
| `sort` | `createdAt:desc` | — | `?sort=createdAt:desc,nomorSurat:asc` |

Di Next.js 16: `searchParams` adalah Promise → `await`.
Input pencarian di-debounce `[ISI: 300ms]`; mengubah filter mereset `page` ke 1.

## 6. Loading, Kosong, Error

| State | Komponen | Catatan |
| :--- | :--- | :--- |
| Loading | `loading.tsx` / `<Suspense fallback={<TableSkeleton />}>` | Skeleton, bukan spinner penuh halaman |
| Kosong | `EmptyState` | Jelaskan penyebab & aksi berikutnya |
| Error | `error.tsx` / `ErrorState` | Pesan aman; log detail di server |
| 404 | `not-found.tsx` | Juga untuk data di luar scope organisasi |
| Akses ditolak | `[ISI: halaman 403 atau redirect ke /dashboard?error=unauthorized]` | |

## 7. Upload File

Batas yang ditetapkan:

| Tipe | Ukuran maks |
| :--- | :--- |
| PDF | 5 MB |
| Gambar (JPEG/PNG) | 2 MB |

> Keputusan: gambar maks **2 MB** (sesuai `AGENTS.md` §9). `03.API_CONVENTIONS.md` §12 masih menulis 5 MB untuk semua tipe — perbarui dokumen itu dan catat di ADR agar konsisten.

UI:
- Validasi tipe & ukuran di sisi client hanya untuk umpan balik cepat; server tetap memvalidasi.
- Tampilkan nama file, ukuran, progres/pending, dan tombol hapus.
- File bersifat privat: tampilkan lewat presigned URL (berlaku 1 jam), bukan URL publik permanen.
- Jangan tampilkan nama file asli dari server sebagai path; nama disimpan acak di backend.

## 8. Akun Organisasi: Field Pengisi

Untuk akun `ORGANIZATIONAL` (PW, PC, PONDOK_INTERNAL, LEMBAGA_EKSTERNAL), setiap form mutasi WAJIB menyertakan `namaPengisi` dan `jabatanPengisi` (audit trail).

- Gunakan `OrgFillerFields` otomatis pada form bila `session.user.accountType === 'ORGANIZATIONAL'`.
- Jangan di-prefill dari nama akun organisasi — pengisi adalah orang yang sedang mengisi.
- `[ISI: apakah nilai terakhir diingat per perangkat?]`

---

## 9. Realtime & Cache

- Repo memakai `@neon/realtime` (live query bertanda tangan dari server, URL dikirim ke client). Server membuat sealed query lewat route `/api/realtime`; credential tidak pernah sampai ke browser.
- `[ISI: fitur mana yang butuh realtime, mis. dashboard metrik, notifikasi]`
- Setelah mutasi, andalkan `revalidatePath`/`revalidateTag` dari server; jangan menyalin data server ke state client tanpa alasan.
- Rich text selalu disanitasi (DOMPurify) sebelum disimpan dan sebelum dirender.

---

## 10. Larangan Keras

- ❌ DILARANG `fetch('/api/...')` dari client untuk mutasi internal.
- ❌ DILARANG mengambil data awal halaman lewat `useEffect`.
- ❌ DILARANG mengandalkan validasi client saja.
- ❌ DILARANG menampilkan stack trace atau pesan error internal ke pengguna.
- ❌ DILARANG form submit tanpa state pending.
- ❌ DILARANG lupa `await` pada `params` dan `searchParams`.
- ❌ DILARANG merender HTML dari input pengguna tanpa sanitasi.
