## 1. Tujuan

Dokumen ini mendefinisikan standar pengujian untuk memastikan kualitas, keandalan, dan keamanan kode backend Platform LIM sebelum di-deploy ke produksi. Tujuannya adalah:

- Mencegah regresi (bug yang muncul kembali setelah diperbaiki).
- Memastikan logika bisnis kritis (penomoran surat, cross-check WK, falak) berjalan benar.
- Memvalidasi otorisasi (RBAC) agar tidak ada akses yang tidak sah.
- Memberikan kepercayaan saat melakukan refactoring atau upgrade dependensi.

## 3. Testing Priority

### 🔴 Priority 1 (WAJIB — Business Critical)

Ini adalah logika bisnis yang jika salah akan menyebabkan dampak serius:

1. **Letter Numbering Logic**
    - Race condition pada penomoran surat
    - Format nomor surat (`{seq}/{level}/{category}/{bulan}/{tahun}`)
    - Reset `currentSeq` per `PeriodeKhidmat`
2. **Authorization (RBAC)**
    - User PC tidak bisa akses data PC lain
    - Role operasional tidak bisa akses modul di luar tugasnya
    - Organizational account isolation
3. **Cross-Check Laporan WK**
    - Perbandingan laporan Guru vs Lembaga pada periode yang sama
    - Deteksi ketidaksesuaian data
4. Falak Calculation
    - Akurasi waktu shalat (Subuh, Maghrib, dll)
    - Manual override oleh Lajnah
    - Penetapan awal bulan (Ramadan, Syawal, Dzul Hijjah)

### 🟡 Priority 2 (SEHARUSNYA)

5. **Zod Validation Schemas**
    - Semua schema validasi input
    - Edge cases (empty string, null, undefined)
6. **Server Actions**
    - Happy path (sukses)
    - Error path (validasi gagal, unauthorized, forbidden)
    - Revalidation setelah mutasi
7. **Organizational Account Flow**
    - Field `namaPengisi` dan `jabatanPengisi` wajib ada
    - Audit trail untuk akun bersama

### 🟢 Priority 3 (NICE TO HAVE)

8. UI Components
    - Cukup E2E, tidak perlu unit test
    - Fokus pada user journey, bukan detail komponen
9. Helper Utils
    - Format tanggal, string helper, dll
    - Hanya test jika logic kompleks

### 4.2 Contoh: Letter Numbering Logic

```typescript
// src/modules/letter/domain/letter-numbering.rules.test.ts
import { describe, it, expect } from 'vitest'
import { generateLetterNumber, formatBulanRomawi } from './letter-numbering.rules'

describe('generateLetterNumber', () => {
  it('should generate correct format for PP level', () => {
    const result = generateLetterNumber({
      seq: 1,
      level: 'PP',
      category: 'H',
      month: 11,
      year: 2026,
      sequenceDigits: 3,
    })
    expect(result).toBe('001/PP/H/XI/2026')
  })

  it('should pad sequence with zeros', () => {
    const result = generateLetterNumber({
      seq: 5,
      level: 'PC.I.8',
      category: 'A',
      month: 1,
      year: 2026,
      sequenceDigits: 4,
    })
    expect(result).toBe('0005/PC.I.8/A/I/2026')
  })

  it('should handle large sequence numbers', () => {
    const result = generateLetterNumber({
      seq: 999,
      level: 'PW.I',
      category: 'K',
      month: 12,
      year: 2026,
      sequenceDigits: 3,
    })
    expect(result).toBe('999/PW.I/K/XII/2026')
  })
})

describe('formatBulanRomawi', () => {
  it('should convert month number to Roman numeral', () => {
    expect(formatBulanRomawi(1)).toBe('I')
    expect(formatBulanRomawi(4)).toBe('IV')
    expect(formatBulanRomawi(9)).toBe('IX')
    expect(formatBulanRomawi(11)).toBe('XI')
    expect(formatBulanRomawi(12)).toBe('XII')
  })

  it('should throw error for invalid month', () => {
    expect(() => formatBulanRomawi(0)).toThrow()
    expect(() => formatBulanRomawi(13)).toThrow()
  })
})
```

### 5.1 Contoh: Server Action

```typescript
// src/modules/letter/application/create-letter.action.test.ts
import { describe, it, expect, beforeEach, vi } from 'vitest'
import { createLetter } from './create-letter.action'
import { prisma } from '@/lib/prisma'
import { getSession } from '@/lib/auth'

// Mock auth
vi.mock('@/lib/auth', () => ({
  getSession: vi.fn(),
}))

describe('createLetter', () => {
  beforeEach(async () => {
    // Clean test database
    await prisma.letter.deleteMany()
    await prisma.letterNumberCounter.deleteMany()
    
    // Reset mock
    vi.mocked(getSession).mockReset()
  })

  it('should reject if user not logged in', async () => {
    vi.mocked(getSession).mockResolvedValue(null)
    
    const formData = new FormData()
    formData.append('perihal', 'Surat Tugas')
    
    const result = await createLetter(formData)
    
    expect(result.success).toBe(false)
    expect(result.error).toBe('Unauthorized')
  })

  it('should reject if user has insufficient role', async () => {
    vi.mocked(getSession).mockResolvedValue({
      user: { id: 'user1', role: 'GURU_BANTU' },
    })
    
    const formData = new FormData()
    formData.append('perihal', 'Surat Tugas')
    
    const result = await createLetter(formData)
    
    expect(result.success).toBe(false)
    expect(result.error).toContain('Forbidden')
  })

  it('should reject invalid data (Zod validation)', async () => {
    vi.mocked(getSession).mockResolvedValue({
      user: { id: 'user1', role: 'OWNER' },
    })
    
    const formData = new FormData()
    formData.append('perihal', '') // Invalid: empty
    
    const result = await createLetter(formData)
    
    expect(result.success).toBe(false)
    expect(result.errors).toBeDefined()
    expect(result.errors?.perihal).toBeDefined()
  })

  it('should create letter in DRAFT status', async () => {
    vi.mocked(getSession).mockResolvedValue({
      user: { id: 'user1', role: 'OWNER' },
    })
    
    const formData = new FormData()
    formData.append('perihal', 'Surat Tugas Guru Bantu')
    formData.append('type', 'KELUAR')
    formData.append('pengirim', 'Pengurus Pusat LIM')
    
    const result = await createLetter(formData)
    
    expect(result.success).toBe(true)
    expect(result.data).toBeDefined()
    expect(result.data?.status).toBe('DIKETIK')
    expect(result.data?.nomorSurat).toBeNull() // Nomor belum di-generate
  })

  it('should generate nomor surat only when status is SENT', async () => {
    // Setup: Create a draft letter first
    const draftLetter = await prisma.letter.create({
      data: {
        type: 'KELUAR',
        perihal: 'Test',
        pengirim: 'PP',
        status: 'DIKETIK',
        createdById: 'user1',
      },
    })
    
    // Mock session
    vi.mocked(getSession).mockResolvedValue({
      user: { id: 'user1', role: 'OWNER' },
    })
    
    // Send letter (change status to SENT)
    const formData = new FormData()
    formData.append('id', draftLetter.id)
    
    const result = await sendLetter(formData)
    
    expect(result.success).toBe(true)
    expect(result.data?.status).toBe('SENT')
    expect(result.data?.nomorSurat).toMatch(/^\d{3}\/PP\/\w+\/\w+\/\d{4}$/)
  })
})
```

### 5.2 Contoh: Cross-Check WK

```typescript
// src/modules/wajib-khidmah/application/cross-check.test.ts
import { describe, it, expect, beforeEach } from 'vitest'
import { crossCheckLaporan } from './cross-check'
import { prisma } from '@/lib/prisma'

describe('crossCheckLaporan', () => {
  beforeEach(async () => {
    await prisma.laporanMingguan.deleteMany()
    await prisma.penugasan.deleteMany()
  })

  it('should detect mismatch between guru and lembaga reports', async () => {
    // Setup: Create penugasan
    const penugasan = await prisma.penugasan.create({
      data: {
        guruBantuId: 'guru1',
        lembagaId: 'lembaga1',
        dosenPenanggungId: 'dosen1',
        tanggalMulai: new Date('2026-01-01'),
        status: 'DIAKTIFKAN',
      },
    })
    
    // Guru reports 20 jamaah
    await prisma.laporanMingguan.create({
      data: {
        penugasanId: penugasan.id,
        pelaporId: 'guru1',
        rolePelapor: 'GURU_BANTU',
        namaPengisi: 'Ahmad',
        jabatanPengisi: 'Guru Bantu',
        periodeMinggu: 1,
        periodeTahun: 2026,
        jumlahJamaahDilakukan: 20,
        aktivitasMingguan: 'Mengajar Nahwu',
        statusHonor: 'SUDAH_SESUAI',
      },
    })
    
    // Lembaga reports 15 jamaah (mismatch!)
    await prisma.laporanMingguan.create({
      data: {
        penugasanId: penugasan.id,
        pelaporId: 'lembaga1',
        rolePelapor: 'LEMBAGA_EKSTERNAL',
        namaPengisi: 'Budi',
        jabatanPengisi: 'Kepala Sekolah',
        periodeMinggu: 1,
        periodeTahun: 2026,
        jumlahJamaahDilakukan: 15,
        aktivitasMingguan: 'Mengajar Nahwu',
        statusHonor: 'SUDAH_SESUAI',
      },
    })
    
    // Run cross-check
    const result = await crossCheckLaporan({
      penugasanId: penugasan.id,
      periodeMinggu: 1,
      periodeTahun: 2026,
    })
    
    expect(result.hasMismatch).toBe(true)
    expect(result.guruJamaah).toBe(20)
    expect(result.lembagaJamaah).toBe(15)
    expect(result.difference).toBe(5)
  })

  it('should return no mismatch if reports are consistent', async () => {
    // Setup similar to above, but both report 20 jamaah
    // ...
    
    const result = await crossCheckLaporan({
      penugasanId: penugasan.id,
      periodeMinggu: 1,
      periodeTahun: 2026,
    })
    
    expect(result.hasMismatch).toBe(false)
    expect(result.difference).toBe(0)
  })
})
```

### 6.2 Contoh: Full Letter Lifecycle

```typescript
// e2e/letter-flow.spec.ts
import { test, expect } from '@playwright/test'

test.describe('Letter Management Flow', () => {
  test.beforeEach(async ({ page }) => {
    // Login as OWNER
    await page.goto('/login')
    await page.fill('[name=email]', 'owner@lim.or.id')
    await page.fill('[name=password]', 'password123')
    await page.click('button[type=submit]')
    await page.waitForURL('/dashboard')
  })

  test('full letter lifecycle: draft → review → approved → sent', async ({ page }) => {
    // Step 1: Create draft
    await page.goto('/dashboard/letters/new')
    await page.fill('[name=perihal]', 'Surat Tugas Guru Bantu')
    await page.fill('[name=pengirim]', 'Pengurus Pusat LIM')
    await page.selectOption('[name=type]', 'KELUAR')
    await page.click('button:has-text("Simpan Draft")')
    
    // Verify draft created
    await expect(page.locator('text=Surat berhasil disimpan')).toBeVisible()
    await expect(page.locator('[data-status="DIKETIK"]')).toBeVisible()
    
    // Step 2: Review
    await page.click('button:has-text("Kirim ke Reviewer")')
    await expect(page.locator('[data-status="REVIEW"]')).toBeVisible()
    
    // Step 3: Approve (as ADMIN_SEKRETARIAT)
    await page.goto('/logout')
    await page.goto('/login')
    await page.fill('[name=email]', 'sekretariat@lim.or.id')
    await page.fill('[name=password]', 'password123')
    await page.click('button[type=submit]')
    
    await page.goto('/dashboard/letters')
    await page.click('text=Surat Tugas Guru Bantu')
    await page.click('button:has-text("Approve")')
    await expect(page.locator('[data-status="APPROVED"]')).toBeVisible()
    
    // Step 4: Send (generate nomor surat)
    await page.click('button:has-text("Kirim Surat")')
    await expect(page.locator('[data-status="SENT"]')).toBeVisible()
    
    // Verify nomor surat generated
    const nomorSurat = await page.locator('[data-nomor-surat]').textContent()
    expect(nomorSurat).toMatch(/^\d{3}\/PP\/\w+\/\w+\/\d{4}$/)
  })

  test('should prevent PC from accessing another PC data', async ({ page }) => {
    // Login as PC Surabaya
    await page.goto('/logout')
    await page.goto('/login')
    await page.fill('[name=email]', 'pc.surabaya@lim.or.id')
    await page.fill('[name=password]', 'password123')
    await page.click('button[type=submit]')
    
    // Try to access PC Malang data via URL manipulation
    await page.goto('/dashboard/letters?orgId=pc-malang-id')
    
    // Should redirect or show empty state
    await expect(page.locator('text=Data tidak ditemukan')).toBeVisible()
  })
})
```

### 10.2 Coverage Gate

```yaml
# Tambahkan ke workflow
- name: Check coverage threshold
  run: |
    COVERAGE=$(cat coverage/coverage-summary.json | jq '.total.lines.pct')
    THRESHOLD=80
    if (( $(echo "$COVERAGE < $THRESHOLD" | bc -l) )); then
      echo "Coverage $COVERAGE% is below threshold $THRESHOLD%"
      exit 1
    fi
```

### 11.1 Test Naming Convention

### 11.2 AAA Pattern (Arrange-Act-Assert)

```typescript
it('should create letter in DRAFT status', async () => {
  // Arrange (Setup)
  vi.mocked(getSession).mockResolvedValue({
    user: { id: 'user1', role: 'OWNER' },
  })
  const formData = new FormData()
  formData.append('perihal', 'Test')
  
  // Act (Execute)
  const result = await createLetter(formData)
  
  // Assert (Verify)
  expect(result.success).toBe(true)
  expect(result.data?.status).toBe('DIKETIK')
})
```

### 11.3 Mocking Strategy

```typescript
// ✅ BENAR: Mock hanya yang diperlukan
```

## 12. Larangan Keras

- ❌ DILARANG menulis test yang bergantung pada data production.
- ❌ DILARANG skip test yang gagal tanpa dokumentasi alasan.
- ❌ DILARANG menulis test yang tidak memiliki assertion (hanya execute).
- ❌ DILARANG menggunakan setTimeout atau sleep di test (gunakan waitFor atau mock timer).
- ❌ DILARANG menulis test yang saling bergantung (setiap test harus independen).
- ❌ DILARANG commit test yang gagal ke repository.
- ❌ DILARANG menurunkan coverage target tanpa review tim.
- ❌ DILARANG menulis test untuk kode yang tidak penting (fokus pada business logic).
- ❌ DILARANG menggunakan snapshot test untuk logika bisnis (hanya untuk UI).
- ❌ DILARANG ignore warning atau error di console saat test berjalan.
