## 4. Penjagaan Route

| Lapisan | Yang dicek |
|---------|------------|
| `proxy.ts` | hanya sesi untuk prefix `/dashboard`, `/admin`, `/profile`. Peta role hanya menyasar `/admin*` yang **tidak ada** di aplikasi. |
| `app/dashboard/layout.tsx` | hanya sesi |
| `app/dashboard/pengguna/page.tsx` | `role === 'OWNER'` |
| Halaman dashboard lain (25 halaman) | **tidak ada cek role/modul** |
| `components/layout/nav-config.ts` | menyembunyikan menu per role (kosmetik) |

Konsekuensi: role apa pun yang punya sesi bisa membuka URL dashboard mana pun dan membaca data yang dikembalikan query halaman tersebut (query sebagian besar tanpa filter organisasi).

## 5. Selisih Kode vs `06.RBAC.md`

| Dokumen | Kode |
|---------|------|
| 15 role | 14 role |
| PW/PC boleh **buat surat** (🔶 🏢) | `createLetterAction` menolak PW/PC |
| ADMIN_BIDANG_* review surat 🔍 (baca) | `submitForReviewAction` mengizinkan mereka mengubah status → REVIEW |
| Surat harus APPROVED sebelum SENT | `SENDABLE_STATUSES` mengizinkan `REVIEW` → SENT |
| `kepengurusan` modul untuk OWNER/ADMIN/PW/PC | modul tidak ada |
| `ACCESS_DENIED` wajib diaudit | 0 pemanggilan `ACCESS_DENIED` |
| PONDOK_INTERNAL punya akses data unitnya | hanya `falak` |

## 6. Titik Rawan yang Mengikuti Peta Ini

1. Tidak ada penjagaan modul di level route → `canAccessModule` hanya kosmetik.
2. Query daftar (`listLetters`, `listPenugasan`, `listJurnal*`, `listLaporan*`, `listUmpanBalik*`, `listDaerahBinaan`, `listSekolahMitra`) tidak memfilter unit/organisasi.
3. Aksi Safari & Pesantren memberi PW/PC akses tulis lintas wilayah.
4. `getLetterById` tanpa cek sesi/pemilik — siapa pun yang punya ID bisa membaca isi surat.
