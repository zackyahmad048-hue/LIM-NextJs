# BACKEND SECURITY STANDARDS

**Project:** LIM Digital Platform  
**Version:** 1.2  
**Status:** Approved  

---

## 1. Tujuan
Dokumen ini mengatur standar keamanan untuk melindungi data organisasi LIM, guru bantu, lembaga, dan surat resmi dari kebocoran, manipulasi, atau akses tidak sah.

---

## 2. Authentication (Better Auth)

- **Session Management**: Disimpan di database (Prisma Adapter). Cookie: `HttpOnly`, `Secure` (production), `SameSite=Lax`.
- **Session Timeout**: 7 hari (default), 30 hari (remember me).
- **Multi-Factor Authentication (MFA)**: **WAJIB** untuk role `OWNER`, `ADMIN_SEKRETARIAT`, dan `ADMIN_BIDANG_*`.
- **Password Policy**: Minimum 8 karakter, kombinasi huruf besar, kecil, dan angka. Hashing: Argon2id.

## 3. Role Hierarchy & Authorization

### 3.1 Daftar Role Lengkap (15 Role Final)

#### 🔴 Level Pusat (PP) — 6 Role
| Role | Deskripsi | Akses Utama |
|------|-----------|-------------|
| `OWNER` | Super Admin / Pengurus Pusat Inti | Akses penuh ke seluruh modul |
| `ADMIN_SEKRETARIAT` | Pengelola Persuratan & Administrasi | CRUD Persuratan, Read semua modul |
| `TIM_WAJIB_KHIDMAH` | Pengelola Modul Wajib Khidmah | CRUD WK, Monitoring Guru Bantu |
| `CONTENT_MANAGER` | Pengelola Portal & Dakwah Digital | CRUD Artikel, Konten Dakwah |
| `ADMIN_BIDANG_SAFARI` | Admin Bidang Safari Ramadan (Pusat) | CRUD Titik Safari, Delegasi, Jurnal, Sidak |
| `ADMIN_BIDANG_PESANTREN_RAMADAN` | Admin Bidang Pesantren Ramadan (Pusat) | CRUD Sekolah Mitra, Bank Materi, Penugasan |

#### 🟡 Level Wilayah & Cabang — 2 Role
| Role | Deskripsi | Akses Utama |
|------|-----------|-------------|
| `PW` | Pengurus Wilayah (Akun Organizational) | Data wilayahnya sendiri, laporan ke PP |
| `PC` | Pengurus Cabang (Akun Organizational) | Data cabangnya sendiri, laporan ke PW |

#### 🟢 Role Operasional — 3 Role (Temporer per Kegiatan)
| Role | Deskripsi | Akses Utama |
|------|-----------|-------------|
| `PANITIA_SAFARI_DAERAH` | Panitia Safari di tingkat PW/PC | Approve jurnal delegasi di wilayahnya |
| `DELEGASI_SAFARI_DAERAH` | Delegasi yang ditugaskan ke daerah | Input jurnal harian, lihat titik tugasnya |
| `PENGAJAR_PESANTREN_RAMADAN` | Pengajar Pesantren Ramadan | Input laporan harian pengajar |

#### 🔵 Role Pendidikan & Lembaga — 3 Role
| Role | Deskripsi | Akses Utama |
|------|-----------|-------------|
| `GURU_BANTU` | Guru yang ditugaskan | Input laporan mingguan WK |
| `LEMBAGA_EKSTERNAL` | Sekolah/TPQ mitra | Input laporan mingguan WK & umpan balik |
| `PONDOK_INTERNAL` | Unit internal pondok (Induk/Unit/Cabang/MHM/Ma'had Aly) | Data pondoknya sendiri |

### 3.3 Flow Khusus: LEMBAGA_EKSTERNAL

**Saat Submit Permohonan:**
- Lembaga eksternal **BELUM** memiliki akun.
- Submit permohonan via form publik (tanpa login).
- Status: `DIAJUKAN`.

**Setelah Disetujui:**
- Sistem otomatis membuatkan akun untuk lembaga tersebut.
- Role: `LEMBAGA_EKSTERNAL`.
- Lembaga bisa login untuk input laporan mingguan WK dan umpan balik.

### 3.4 Sub-Tipe PONDOK_INTERNAL

Role `PONDOK_INTERNAL` mencakup semua unit internal pondok. Sub-tipe disimpan di tabel `UnitOrganisasi` dengan field `subKategori`:

**Contoh Sub-Tipe Cabang (20+):**

### 3.5 Organizational Isolation (Row-Level Security)

User dari PC Surabaya **TIDAK BOLEH** melihat data PC Malang. Validasi otorisasi **WAJIB** dilakukan di dalam Server Action.

```typescript
// ✅ BENAR: Selalu filter berdasarkan organisasi user
const data = await prisma.laporan.findMany({
  where: { organisasiId: session.user.organisasiId }
})

// ❌ SALAH: Tidak ada filter organisasi
const data = await prisma.laporan.findMany()
```

### 4. Input Validation (Zod — WAJIB)

**TIDAK ADA** data dari client yang dipercaya tanpa validasi.

```typescripts
// ✅ WAJIB di awal Server Action
const parsed = schema.safeParse(input)
if (!parsed.success) {
  return { success: false, errors: parsed.error.flatten().fieldErrors }
}
```
- **Sanitization**: Untuk rich text (isi surat, artikel), gunakan `DOMPurify`. Untuk plain text, Zod `z.string().trim()` sudah cukup.
---
### 5. SQL Injection Prevention

- Gunakan **Prisma Client** untuk semua query.
- **DILARANG** menggunakan `$queryRaw` atau `$queryRawUnsafe` dengan string concatenation.
- Jika harus raw query, gunakan parameterized query:

```typescript
  await prisma.$queryRaw`SELECT * FROM "User" WHERE email = ${email}`
  ```
  ---
  ### 6. File Upload Security

  **Validasi Server-Side**

  ```typescript
  const ALLOWED_TYPES = ['application/pdf', 'image/jpeg', 'image/png']
const MAX_SIZE = 5 * 1024 * 1024 // 5MB

if (!ALLOWED_TYPES.includes(file.type)) throw new Error('Tipe file tidak diizinkan')
if (file.size > MAX_SIZE) throw new Error('Ukuran file melebihi batas')
```
**Storage Rules**

- Simpan di **Cloudflare R2** atau **AWS S3** (bucket private).
- **DILARANG** menyimpan file di folder `/public` atau `/uploads` server.
- Generate **Presigned URL** untuk akses sementara (expired 1 jam).
- Generate nama file acak (UUID/CUID), JANGAN pakai nama asli file.
---

### 7. Environment Variables

- `NEXT_PUBLIC_*` → Boleh diakses client (browser).
- Tanpa prefix → HANYA di server. Contoh: `DATABASE_URL`, `BETTER_AUTH_SECRET`.
- **DILARANG** commit `.env.local` ke Git.
- **DILARANG** hardcode secret di source code.
---

### 8. Audit Trail

Setiap aksi kritis WAJIB dicatat di tabel `AuditLog`:

-Login/logout
-Perubahan status surat (terutama ke `SENT`)
-Perubahan status penugasan (ke `DICABUT`, `PULANG`)
-Hapus data atau perubahan role/hak akses

---
### 9. Larangan Keras Keamanan

- ❌ DILARANG bypass validasi Zod di Server Actions.
- ❌ DILARANG mengekspos DATABASE_URL atau secret keys ke client.
- ❌ DILARANG memberikan akses OWNER atau ADMIN ke akun shared tanpa MFA.
- ❌ DILARANG menyimpan file sensitif di repository atau folder publik.
- ❌ DILARANG user PW/PC mengakses data organisasi lain (Row-Level Security wajib).
