## 1. Tujuan

Dokumen ini mendefinisikan desain backend target untuk LIM Digital Platform: model data, integritas, isolasi tenant, kontrak API, observability, dan rencana migrasi. Dokumen ini menjadi acuan implementasi F1–F5 (lihat §12).

**Ruang lingkup:** 11 domain bisnis, 50 model Prisma saat ini, Next.js 16 App Router (Server Actions + Route Handlers `/api/v1`), Prisma 6, Neon PostgreSQL, Better Auth, Upstash Redis.

**Bukan ruang lingkup:** desain UI, copywriting, infra non-DB (CDN, DNS), penggantian stack.

## 3. Prinsip Desain

1. **Correctness > convenience.** Invarian bisnis ditegakkan di DB (constraint/index/transaction), bukan hanya di UI.
2. **Defense in depth.** AuthZ di proxy + Server Action/API handler + query scope + RLS DB.
3. **Tenant isolation by default.** Data milik organisasi selalu punya `unitId`; query tanpa tenant context gagal.
4. **Small, auditable mutations.** Setiap mutasi kritis mencatat AuditLog + actor + request-id.
5. **Prisma 6 pinned.** Jangan gunakan API/dokumen Prisma 7/8. Referensi: `/prisma/web/__branch__v6`.
6. **Explicit over implicit.** Enum multiline, relasi bidirectional, FK eksplisit, `onDelete` eksplisit.

## 4. Arsitektur Target

```text
Client (Browser/Mobile/3rd party)
  │
  ├─ Server Actions (internal UI mutation) ──┐
  └─ Route Handlers /api/v1/* (public/ext) ──┤
                                             ▼
                               lib/api/handler (request-id, CORS, rate-limit,
                                                auth, idempotency, error mapping)
                                             ▼
                               modules/<domain>/presentation (DTO/Zod)
                                             ▼
                               modules/<domain>/application (use case, tx boundary)
                                             ▼
                               modules/<domain>/infrastructure (Prisma repo, storage)
                                             ▼
                               lib/prisma + $extends (soft-delete, audit, tenant guard)
                                             ▼
                               Neon PostgreSQL (RLS FORCE, constraints, indexes)
```

### 4.1 Batas Lapisan (tetap)

- `domain/`: pure TS + Zod, tanpa `@/generated/client`, tanpa `next/*`.
- `application/`: orkestrasi, transaksi, keputusan bisnis.
- `infrastructure/`: satu-satunya import `@/generated/client`.
- `presentation/`: validasi input, authz, DTO, cache revalidation. Tidak query Prisma langsung.

### 4.2 Kontrak Respons

**Server Action** (`ActionResult<T>`):
```ts
type ActionResult<T> = { success: boolean; data?: T; error?: string; errors?: Record<string, string[]> }
```

**API Route**:
```json
{ "success": true, "data": ..., "meta": { "page":1,"limit":20,"total":100,"totalPages":5 }, "requestId":"..." }
{ "success": false, "error": { "code":"VALIDATION_ERROR","message":"...","details":{...} }, "requestId":"..." }
```

Error code kanonik (perluas `lib/api/errors.ts`): `BAD_REQUEST`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `VALIDATION_ERROR`, `RATE_LIMITED`, `INTERNAL_ERROR`, `IDEMPOTENCY_REPLAY`.

## 5. Desain Data (Lintas Domain)

### 5.1 Kolom Standar

Semua model bisnis mutable:
```prisma
id          String    @id @default(cuid())
createdAt   DateTime  @default(now())
updatedAt   DateTime  @updatedAt
createdById String?
updatedById String?
deletedAt   DateTime? // hanya entitas yang butuh soft delete
```

Model immutable/log append-only (contoh: `AuditLog`, `LetterLog`, `JurnalHarianSafari` setelah final): minimal `id`, `createdAt`, tanpa `updatedAt/deletedAt` kecuali dibutuhkan.

### 5.2 Soft Delete

| Model | Mode | Alasan |
|---|---|---|
| `User`, `Letter`, `Penugasan`, `Article`, `KontenDakwah`, `Lembaga`, `PermohonanGuruBantu` | Soft delete | Riwayat/audit/legal |
| `DetailKitab`, `PendaftaranEvent`, `JurnalHarianSafari`, `LaporanHarian*`, `ApprovalJurnal`, `PilihanMateriSekolah`, `LetterLog` | Hard/cascade child | Tidak punya nilai historis independen |
| `AuditLog` | Append-only, no delete | Forensik |

**Penegakan F3:** Prisma `$extends` query extension menambah `where: { deletedAt: null }` default untuk model soft-delete, dengan escape hatch eksplisit `includeDeleted: true` hanya di repository audit/admin.

### 5.3 Audit Log

Target shape:
```prisma
model AuditLog {
  id        String   @id @default(cuid())
  userId    String?
  action    String   // e.g. LETTER_SENT, ROLE_CHANGED, ACCESS_DENIED
  entity    String
  entityId  String
  metadata  Json?
  ipAddress String?
  requestId String?
  createdAt DateTime @default(now())
  user User? @relation(fields: [userId], references: [id])
  @@index([userId])
  @@index([action])
  @@index([entity, entityId])
  @@index([createdAt])
}
```

Aksi wajib audit: login/logout, role change, letter SENT, penugasan DICABUT/SELESAI, delete, ACCESS_DENIED, approval/rejection permohonan, perubahan config falak.

### 5.4 Indexing & Unique Baseline

Aturan:
- Semua FK ber-index.
- Field filter/sort (`status`, `createdAt`, `tanggal`, `slug`, `nomorSurat`) ber-index.
- Unique bisnis eksplisit.
- Hindari index duplikat dari `@unique`.
- Partial index/unique untuk kondisi bisnis (raw SQL migration Prisma 6).

Kandidat F1:
- `DelegasiSafari @@unique([titikId, userId])`
- `JurnalHarianSafari @@unique([delegasiId, tanggal])`
- `LaporanBulananBinaan @@unique([daerahBinaanId, tahun, bulan])`
- `LaporanMingguan @@unique([penugasanId, periodeTahun, periodeMinggu])` (divalidasi dulu terhadap data existing)
- `JadwalShalat @@unique([configId, tanggal])` (ganti `tanggal @unique`)
- `PeriodeKhidmat @@unique([tahunMulai, tahunSelesai])`
- Partial unique: satu `FalakConfig` aktif (`WHERE "isActive" = true`)
- Partial index: `User/Letter/Penugasan WHERE "deletedAt" IS NULL`

## 6. Tenancy & Isolasi Data (RLS)

### 6.1 Keputusan

Pilih **unitId + PostgreSQL RLS** (ADR-010). Rantai relasi saja tidak cukup untuk 11 domain dengan banyak tabel anak.

### 6.2 Model Tenancy

- `UnitOrganisasi` dapat `parentId` untuk hierarki (PP/PW/PC/Pondok/Lembaga internal).
- Entitas aggregate root milik organisasi mendapat `unitId String?` + FK + index.
- `AuthzSubject` diperluas: `userId, role, accountType, unitId, lembagaId, scope` (`PUSAT|UNIT|LEMBAGA|SELF|PUBLIC`).

Kandidat `unitId`:

| Domain | Tabel dengan `unitId` | Catatan |
|---|---|---|
| Kepengurusan | `UnitOrganisasi` (self), `OrganizationalAccount` (sudah via unitId) | root |
| Wajib Khidmah | `Lembaga`, `Penugasan`, `PermohonanGuruBantu`, `EvaluasiKasus`, `EvaluasiInduk` | `LaporanMingguan` ikut via Penugasan atau denorm |
| Persuratan | `Letter` | sudah punya `createdById`; tambah `unitId` untuk scope PW/PC |
| Safari | `TitikSafari`, `DelegasiSafari` | jurnal/sidak ikut delegasi |
| Pesantren | `SekolahMitra`, `PenugasanPesantren` | laporan ikut penugasan |
| Dakwah | `KontenDakwah` opsional | pusat-scope; unitId null = pusat |
| Daerah Binaan | `DaerahBinaan` | laporan ikut daerah |

### 6.3 RLS Runtime

```text
Request -> auth -> resolve AuthzSubject
       -> withTenant(subject, async (tx) => {
            await tx.$executeRaw`SELECT set_config('app.scope', ${scope}, true)`;
            await tx.$executeRaw`SELECT set_config('app.unit_id', ${unitId ?? ''}, true)`;
            await tx.$executeRaw`SELECT set_config('app.user_id', ${userId}, true)`;
            ...queries via tx...
          })
```

Policy template:
```sql
ALTER TABLE "Letter" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "Letter" FORCE ROW LEVEL SECURITY;

CREATE POLICY letter_select ON "Letter" FOR SELECT USING (
  current_setting('app.scope', true) = 'PUSAT'
  OR "unitId" = current_setting('app.unit_id', true)
);
CREATE POLICY letter_write ON "Letter" FOR ALL USING (
  current_setting('app.scope', true) = 'PUSAT'
  OR "unitId" = current_setting('app.unit_id', true)
) WITH CHECK (
  current_setting('app.scope', true) = 'PUSAT'
  OR "unitId" = current_setting('app.unit_id', true)
);
```

### 6.4 DB Roles & Env

| Env | User DB | Privilege | Pakai |
|---|---|---|---|
| `DATABASE_URL` | `lim_app` | NOSUPERUSER, NOBYPASSRLS | runtime app |
| `DIRECT_URL` | owner/migration | normal | `prisma migrate deploy`, maintenance |

Prisma 6 schema:
```prisma
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}
```

Neon pooled connection + transaction mode: **hanya `SET LOCAL`** di dalam transaksi; jangan `SET` session-level.

### 6.5 Guard Aplikasi

F3 menambah Prisma client extension: model tenant-scoped menolak query jika tidak berjalan dalam `withTenant` context (AsyncLocalStorage / tx marker). Ini mencegah bypass tak sengaja.

## 7. Per-Domain Blueprint

### 7.1 Auth & Authorization

- **Entitas:** `User`, `Session`, `Account`, `Verification`, `Apikey`, (F1) `TwoFactor`.
- **Invarian:** email unique; role dari enum 15; `accountType` PERSONAL/ORGANIZATIONAL. Akun ORGANIZATIONAL wajib punya `OrganizationalAccount.unitId`.
- **AuthZ:** RBAC matrix `06.RBAC.md` adalah sumber. Effective permission = role + active `PenugasanStruktural` + active `PeriodeKhidmat`.
- **API:** session via Better Auth; `/api/v1/*` menerima session cookie atau `x-api-key`/Bearer.
- **Audit:** login, logout, failed login threshold, role change, API key create/revoke.

### 7.2 Kepengurusan

- **Entitas:** `PeriodeKhidmat`, `UnitOrganisasi`, `Bidang`, `Jabatan`, `PenugasanStruktural`, `OrganizationalAccount`.
- **Invarian:** satu `PeriodeKhidmat.isActive=true` (partial unique). `UnitOrganisasi.levelCode` unique. `PenugasanStruktural` unique `(userId,jabatanId,periodeId)`.
- **Perubahan F1:** `UnitOrganisasi.parentId`, timestamps.
- **API:** read-heavy, cache tag `org-structure`. Mutasi hanya OWNER/ADMIN_SEKRETARIAT.

### 7.3 Wajib Khidmah

- **Aggregate root:** `Lembaga`, `Penugasan`, `PermohonanGuruBantu`.
- **State machine Penugasan:** `DIAJUKAN -> DIAKTIFKAN -> SELESAI|DICABUT|DIPERPANJANG`, `DIAJUKAN -> DITOLAK`.
- **Invarian:** `LaporanMingguan` unique `(penugasanId, periodeTahun, periodeMinggu)`; `PermohonanGuruBantu` publik rate-limited; `namaPengisi/jabatanPengisi` wajib untuk akun organizational.
- **Transaksi:** approval permohonan (buat/update Lembaga + RiwayatPermohonan + AuditLog) dalam satu tx. Cross-check WK oleh TIM_WK butuh query konsisten; gunakan Serializable bila update counter/status bersaing.
- **Index:** `Penugasan(guruBantuId,status)`, `LaporanMingguan(penugasanId,periodeTahun,periodeMinggu)`, `Lembaga(unitId,status,kategori)`.

### 7.4 Persuratan

- **Aggregate root:** `Letter`.
- **State machine:** `DIKETIK -> REVIEW -> APPROVED -> SENT -> ARCHIVED`.
- **Invarian emas:** nomor surat digenerate **hanya** saat transisi ke `SENT`; reset counter per `PeriodeKhidmat` aktif. Format nomor ditentukan domain rule, bukan client.
- **Numbering tx (F3):**
  ```ts
  await withRetryP2034(() => prisma.$transaction(async (tx) => {
    const counter = await tx.letterNumberCounter.upsert({
      where: { periodId_levelCode_categoryCode: { periodId, levelCode, categoryCode } },
      create: { periodId, levelCode, categoryCode, currentSeq: 1 },
      update: { currentSeq: { increment: 1 } },
    })
    // create number, update letter status SENT, write LetterLog(LetterAction.DIKIRIM)
  }, { isolationLevel: Prisma.TransactionIsolationLevel.Serializable }))
  ```
- **LetterLog:** ubah `action` ke `LetterAction` (F1). Simpan `requestId`, `userId`, `notes`.
- **API:** sudah ada `/api/v1/letters`; jadikan reference implementation untuk domain lain.

### 7.5 Safari Ramadan

- **Entitas:** `TitikSafari`, `DelegasiSafari`, `JurnalHarianSafari`, `ApprovalJurnal`, `LaporanSidak`.
- **Invarian:** satu delegasi aktif per (titik,user) untuk periode/event yang sama — minimal `@@unique([titikId,userId])` atau unique partial by status aktif (perlu keputusan bisnis; F1 mulai dari unique composite + validasi app). Jurnal harian unique `(delegasiId,tanggal)`.
- **Scope:** PW/PC hanya wilayahnya (`unitId` titik/delegasi).

### 7.6 Pesantren Ramadan

- **Entitas:** `SekolahMitra`, `BankMateri`, `PilihanMateriSekolah`, `PenugasanPesantren`, laporan/umpan balik.
- **Invarian:** `PilihanMateriSekolah` sudah unique `(sekolahId,materiId)`. Penugasan tidak overlap untuk pengajar pada tanggal sama (validasi app; index pendukung).
- **Kurikulum lock:** sebelum Ramadan status materi bisa berubah; saat pelaksanaan, perubahan butuh role pusat + audit.

### 7.7 Digital Falak

- **Entitas:** `FalakConfig`, `JadwalShalat`, `PenetapanAwalBulan`.
- **Invarian:** satu config aktif (partial unique). `JadwalShalat` unique `(configId,tanggal)`. Override manual butuh `catatanOverride`.
- **Cache:** `'use cache'`, `cacheLife('hours')`, tag `falak-jadwal`, `falak-config`; `revalidateTag` saat update.

### 7.8 CMS & Dakwah Digital

- **Entitas:** `Article`, `ArticleCategory`, `KontenDakwah`, `PendaftaranEvent`.
- **Invarian:** slug unique; publish hanya OWNER/CONTENT_MANAGER; konten dakwah punya workflow `DRAFT->PENDING_REVIEW->APPROVED->PUBLISHED`.
- **Sanitasi:** rich text/HTML wajib DOMPurify sebelum simpan/render.
- **Cache:** tag `articles`, `dakwah-konten`.

### 7.9 Daerah Binaan

- **Entitas:** `DaerahBinaan`, `LaporanBulananBinaan`.
- **Invarian:** laporan bulanan unique `(daerahBinaanId, tahun, bulan)`. Scope PW/PC.

### 7.10 Lembaga Eksternal

- **Flow:** form publik (tanpa login) -> `PermohonanGuruBantu`/`Lembaga` status DIAJUKAN/CALON -> review pusat -> approve -> auto-create User role `LEMBAGA_EKSTERNAL` + `Lembaga.userId`.
- **Keamanan:** rate limit ketat, captcha opsional, validasi Zod, file upload private, audit trail.

### 7.11 Audit & Observability

- **AuditLog:** append-only, Json metadata, requestId.
- **App log:** `console.error('[module.action]', { requestId, ... })`, tanpa secret/PII sensitif.
- **Prisma:** query log middleware di dev; slow query threshold di observability.

## 8. Desain API

### 8.1 Kapan Server Action vs Route Handler

| Kebutuhan | Gunakan |
|---|---|
| Mutasi dari UI internal | Server Action di `modules/*/presentation/actions` |
| Read untuk RSC | Query function / server component |
| Endpoint publik, webhook, integrasi, mobile | Route Handler `/api/v1/...` |
| File upload presign | Route Handler (sudah ada `/api/v1/uploads/presign`) |

### 8.2 Kontrak Endpoint

- Validasi: Zod di boundary. Unknown field ditolak/strip sesuai schema.
- Auth: `createApiHandler({ auth: 'required'|'optional'|'public', rateLimit, idempotent })`.
- AuthZ: cek permission + scope tenant sebelum query.
- Pagination: offset (`page,limit`) untuk sederhana; cursor untuk audit/log/feed besar (F4).
- Idempotency: POST mutasi penting wajib dukung `Idempotency-Key`.
- CORS: allowlist dari env, default localhost dev.

### 8.3 Cache & Revalidation

- Mutasi sukses: `revalidatePath`/`revalidateTag`.
- Data publik read-heavy: `'use cache'` + `cacheTag` + `cacheLife`.
- Jangan pakai `unstable_cache`.

### 8.4 OpenAPI & Contract Test

- Setiap route `/api/v1` punya Zod request/response schema.
- `bun run api:spec` menghasilkan OpenAPI; `api:spec:check` di CI.
- Contract test minimal: auth required, validation 422, happy path, scope isolation.

## 9. Transaksi, Concurrency, dan Idempotency

| Kasus | Strategi |
|---|---|
| Nomor surat | Serializable tx + counter upsert increment + retry P2034 |
| Approval permohonan | Tx tunggal: update permohonan + upsert lembaga/riwayat + audit |
| Cross-check WK | Tx + unique constraint laporan mingguan |
| Publish artikel | Tx kecil: update status + audit + revalidateTag |
| API POST eksternal | `Idempotency-Key` (sudah ada `lib/api/idempotency.ts`) |

Pola retry P2034 (Prisma 6):
```ts
for (let i = 0; i < MAX; i++) {
  try { return await prisma.$transaction(fn, { isolationLevel: Prisma.TransactionIsolationLevel.Serializable }) }
  catch (e) { if (e?.code === 'P2034' && i < MAX-1) continue; throw e }
}
```

- Zod semua input. Tidak ada raw SQL string concatenation.
- RBAC server-side. Proxy bukan satu-satunya guard.

## 13. Risiko & Mitigasi

| Risiko | Mitigasi |
|---|---|
| RLS memaksa semua query tenant dalam tx | Bungkus di `withTenant`; lint rule/extension guard; tes integrasi |
| Neon pooler + SET LOCAL | Pastikan transaction mode; gunakan `$transaction`; jangan session SET |
| Migration kolom NOT NULL pada data lama | Tambah nullable -> backfill -> set NOT NULL di migration terpisah |
| `LetterLog.action` ganti tipe | SQL `USING CASE` di migration; backup sebelum deploy |
| Unique baru bentrok data existing | Jalankan query deteksi duplikat sebelum migration; bersihkan/merge |
| Performa RLS | Index `unitId`; benchmark query utama; pertimbangkan policy sederhana |

- **Tenant-scoped root (perlu `unitId`)**: Lembaga, Penugasan, PermohonanGuruBantu, EvaluasiKasus, EvaluasiInduk, Letter, TitikSafari, DelegasiSafari, SekolahMitra, PenugasanPesantren, DaerahBinaan, KontenDakwah (opsional).
- **Child/tenant-inherited**: DetailKitab, RiwayatAkademik, RiwayatGuruBantu, LetterLog, LaporanMingguan, JurnalHarianSafari, ApprovalJurnal, LaporanSidak, PilihanMateriSekolah, LaporanHarianPengajar, LaporanHarianKoordinator, UmpanBalikPeserta, UmpanBalikPusat, LaporanBulananBinaan, PendaftaranEvent.
- **Global/config**: PeriodeKhidmat, UnitOrganisasi, Bidang, Jabatan, LetterPeriod, LetterNumberCounter, FalakConfig, JadwalShalat, PenetapanAwalBulan, BankMateri, ArticleCategory, TahunAjaran.
- **Auth/infra**: User, Session, Account, Verification, Apikey, AuditLog.
- **Soft-delete**: User, Penugasan, Letter (+ kandidat: Article, Lembaga, PermohonanGuruBantu, KontenDakwah).

*Inventaris detail field-level dibuat saat F1 migration review.*
