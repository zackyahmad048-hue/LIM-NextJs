### ROLE-BASED ACCESS CONTROL (RBAC) MATRIX

**Project:** LIM Digital Platform
**Version:** 1.2
**Status:** Approved

---

### 1. Tujuan

Dokumen ini mendefinisikan hak akses(permissions) untuk 15 role di Platform LIM. Matriks ini menjadi acuan mutlak untuk implementasi otorisasi di Server Actions dan middleware.

---

### 2. Legenda Permission

| Simbol | Arti                         | Deskripsi                                |
| ------ | ---------------------------- | ---------------------------------------- |
| ✅      | \*\*Full Access\*\*          | Create, Read, Update, Delete             |
| 🔶     | \*\*Limited Access\*\*       | Read + Update (tidak bisa Delete)        |
| 🔍     | \*\*Read Only\*\*            | Hanya bisa melihat data                  |
| ➕      | \*\*Create Only\*\*          | Hanya bisa membuat data baru             |
| ✏️     | \*\*Update Only\*\*          | Hanya bisa mengedit data sendiri         |
| ❌      | \*\*No Access\*\*            | Tidak punya akses sama sekali            |
| 🌍     | \*\*Global Scope\*\*         | Bisa akses data seluruh organisasi       |
| 🏢     | \*\*Organizational Scope\*\* | Hanya data organisasinya sendiri (PW/PC) |
| 👤     | \*\*Personal Scope\*\*       | Hanya data milik user itu sendiri        |

### 4.Implementasi Teknis

## 4.1 Middleware Authorization

```typescript
// src/middleware.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'
import { getSession } from '@/lib/auth'

export async function middleware(request: NextRequest) {
  const session = await getSession()
  
  if (!session) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  const { role } = session.user
  const pathname = request.nextUrl.pathname

  // Cek akses berdasarkan role dan path
  if (pathname.startsWith('/dashboard/safari') && !canAccessSafari(role)) {
    return NextResponse.redirect(new URL('/dashboard', request.url))
  }

  return NextResponse.next()
}

function canAccessSafari(role: string): boolean {
  const allowedRoles = [
    'OWNER',
    'ADMIN_BIDANG_SAFARI',
    'PW',
    'PC',
    'PANITIA_SAFARI_DAERAH',
    'DELEGASI_SAFARI_DAERAH'
  ]
  return allowedRoles.includes(role)
}
```
### 4.2 Server Action Authorization

```typescript
// Di setiap Server Action
export async function createLetter(formData: FormData) {
  const session = await getSession()
  if (!session) return { success: false, error: 'Unauthorized' }

  // Cek role
  const allowedRoles = ['OWNER', 'ADMIN_SEKRETARIAT', 'ADMIN_BIDANG_SAFARI']
  if (!allowedRoles.includes(session.user.role)) {
    return { success: false, error: 'Forbidden: Insufficient permissions' }
  }

  // Cek scope (organizational isolation)
  if (session.user.role === 'PW' || session.user.role === 'PC') {
    // Filter data berdasarkan organizational account
    const data = await prisma.letter.findMany({
      where: { organizationalAccountId: session.user.organizationalAccountId }
    })
  }

  // ... lanjutkan logika bisnis
}
```

### 5 Audit Trail untuk Otorisasi

Setiap kali user mencoba akses yang tidak diizinkan, **WAJIB** dicatat di `AuditLog`:

```typescript
await prisma.auditLog.create({
  data: {
    userId: session.user.id,
    action: 'ACCESS_DENIED',
    entity: 'Letter',
    entityId: letterId,
    metadata: JSON.stringify({
      attemptedAction: 'DELETE',
      userRole: session.user.role,
      reason: 'Insufficient permissions'
    }),
    ipAddress: request.headers.get('x-forwarded-for')
  }
})
```

### 6 Larangan Keras Otorisasi

- ❌ DILARANG bypass otorisasi di Server Actions.
- ❌ DILARANG mengandalkan validasi di UI saja (client-side).
- ❌ DILARANG user PW/PC mengakses data organisasi lain.
- ❌ DILARANG role operasional (`DELEGASI_SAFARI_DAERAH`) mengakses modul di luar tugasnya.
- ❌ DILARANG memberikan role `OWNER` atau `ADMIN` tanpa MFA.
