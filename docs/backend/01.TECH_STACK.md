## 1. Core Backend Stack

Platform ini dibangun menggunakan teknologi *latest stable* untuk menjamin performa, keamanan, dan *developer experience* yang optimal.

| Teknologi | Versi | Peran & Alasan Pemilihan |
| :--- | :--- | :--- |
| **Next.js** | **16.x** | Framework fullstack. App Router, Turbopack (default), React Compiler. Mutasi data utama via Server Actions. |
| **Runtime** | **Bun** | Package manager & runtime. Lebih cepat dari npm/pnpm untuk install dan eksekusi. |
| **Prisma** | **6.x** | ORM modern dengan Native TypeScript. Query engine cepat dan type-safe. |
| **Database** | **Neon** | Serverless PostgreSQL. Mendukung *database branching* dan *autoscaling*. |
| **Auth** | **Better Auth** | Library autentikasi *database-agnostic*. Mendukung native **Organizational Accounts** (Multi-tenant). |
| **Validation** | **Zod** | Schema validation untuk TypeScript. WAJIB untuk validasi SEMUA input dari client. |
| **Styling** | **Tailwind CSS v4** | CSS-first configuration (tanpa `tailwind.config.ts`). |
| **UI Components** | **shadcn/ui** | Registry terbaru, kompatibel dengan Tailwind v4 & React 19. |
| **Animation** | **Framer Motion v12** | Layout animations & gestures. |

## 2. Arsitektur Backend (DDD)

Backend menggunakan pola **Modular Monolith** dengan prinsip **Domain-Driven Design (DDD)**. Setiap modul bisnis diisolasi dalam *bounded context*.

### Struktur Layering (Wajib Dipatuhi)
```text
src/modules/<nama-domain>/
├── domain/           # Entitas bisnis murni, Value Objects, Interface Repository
├── application/      # Use Cases, Service Logic, Orkestrasi bisnis
├── infrastructure/   # Implementasi Repository (Prisma Client), Integrasi Pihak Ketiga
└── presentation/     # Server Actions, API Routes, dan DTOs
```
---
### Aturan Batas (Boundary Rules)

### A. Konfigurasi Prisma

- Prisma Client di-generate ke folder khusus: `@/generated/client`.
- **DILARANG** impor langsung dari `@prisma/client`.
- Gunakan `prisma.$transaction` untuk operasi multi-tabel atau pencegahan *Race Condition*.

### B. Indexing & Performa Query

Setiap field yang digunakan untuk `where`, `orderBy`, atau relasi WAJIB diberi index:

```Prisma
model LaporanMingguan {
  penugasanId String
  @@index([penugasanId])
  @@index([periodeTahun, periodeMinggu])
}
```

### C. Mencegah N+1 Query Problem

Selalu gunakan `include` atau `select` saat mengambil data relasi:

```typescript
// ✅ BENAR (Single Query)
const penugasan = await prisma.penugasan.findMany({
  include: { 
    guruBantu: { select: { user: { select: { namaLengkap: true } } } } 
  }
});
```

### 4. Autentikasi & Otorisasi

### A. Model Akun (Personal vs Organizational)

Sistem LIM memiliki dua jenis entitas pengguna:

1. Personal Account: 1 Orang = 1 Akun
- Role: `OWNER`, `ADMIN_SEKRETARIAT`, `TIM_WAJIB_KHIDMAH`, `CONTENT_MANAGER`, `ADMIN_BIDANG_SAFARI`, `ADMIN_BIDANG_PESANTREN_RAMADAN`, `GURU_BANTU`, `PANITIA_SAFARI_DAERAH`, `DELEGASI_SAFARI_DAERAH`, `PENGAJAR_PESANTREN_RAMADAN`

2. Organizational Account: 1 Organisasi = 1 Akun Bersama
- Role: `PW`, `PC`, `PONDOK_INTERNAL`, `LEMBAGA_EKSTERNAL`
- **Aturan Kritis**: Setiap mutasi data dari akun ini WAJIB menyertakan field `namaPengisi` dan `jabatanPengisi` untuk audit trail.

### B. Daftar Role Final (15 Role)

🔴 **Level Pusat (PP) — 6 Role**

| Role                               | Fungsi Utama                           |
| ---------------------------------- | -------------------------------------- |
| `OWNER`                          | Super Admin, akses penuh               |
| `ADMIN_SEKRETARIAT`              | Kelola persuratan & administrasi pusat |
| `TIM_WAJIB_KHIDMAH`              | Kelola modul Wajib Khidmah             |
| `CONTENT_MANAGER`                | Kelola portal, artikel, dakwah digital |
| `ADMIN_BIDANG_SAFARI`            | Admin Bidang Safari Ramadan (pusat)    |
| `ADMIN_BIDANG_PESANTREN_RAMADAN` | Admin Bidang Pesantren Ramadan (pusat) |

🟡 **Level Wilayah & Cabang — 2 Role**

| Role   | Fungsi Utama                           |
| ------ | -------------------------------------- |
| `PW` | Pengurus Wilayah (akun organizational) |
| `PC` | Pengurus Cabang (akun organizational)  |

🟢 **Role Operasional (Temporer) — 3 Role**

| Role                           | Fungsi Utama                            |
| ------------------------------ | --------------------------------------- |
| `PANITIA_SAFARI_DAERAH`      | Panitia Safari di tingkat PW/PC         |

🔵 Role Pendidikan & Lembaga — 3 Role

| Role                  | Fungsi Utama                                            |
| --------------------- | ------------------------------------------------------- |
| `GURU_BANTU`        | Guru yang ditugaskan ke lembaga                         |
| `LEMBAGA_EKSTERNAL` | Sekolah/TPQ mitra (setelah permohonan disetujui)        |
| `PONDOK_INTERNAL`   | Unit internal pondok (Induk/Unit/Cabang/MHM/Ma'had Aly) |

### C. Flow Khusus: LEMBAGA_EKSTERNAL

**Saat Submit Permohonan:**
- Lembaga eksternal **BELUM** memiliki akun.
- Submit permohonan via form publik (tanpa login).
- Status: `DIAJUKAN`.

**Setelah Disetujui:**
- Sistem otomatis membuatkan akun untuk lembaga tersebut.
- Role: `LEMBAGA_EKSTERNAL`.
- Lembaga bisa login untuk input laporan mingguan WK dan umpan balik.

## D. Sub-Tipe PONDOK_INTERNAL

Role `PONDOK_INTERNAL` mencakup semua unit internal pondok. Sub-tipe disimpan di tabel `UnitOrganisasi` dengan field `subKategori`:

**Contoh Sub-Tipe Unit (20+):**
- Unit HMC, Unit P3HM, Unit P3TQ, Unit HMA, dll.

**Contoh Sub-Tipe Cabang (20+):**
- Lirboyo IV Cabang Santren, Lirboyo V Cabang Majalengka, dll.

### E. Role-Based Access Control (RBAC)

- Otorisasi tidak hanya mengecek `role` statis di tabel `User`.
- Hak akses harus di-join dengan tabel `PenugasanStruktural` dan `PeriodeKhidmat` yang `isActive = true`.
- Implementasi **Row-Level Security Logic**: User dari PC Surabaya tidak boleh melihat data PC Malang.

### 5. Alur Data & Validasi

Semua mutasi data (Create, Update, Delete) dari client WAJIB melalui **Server Actions** (`'use server'`), bukan REST API (kecuali untuk webhook/publik).

**The Golden Flow (Alur Wajib)**

1. Client: Submit form.
2. Validation (Zod): Server Action memvalidasi payload. Jika gagal, return error segera.
3. Authorization (Better Auth): Cek session dan hak akses user.
4. Business Logic (Application): Proses aturan bisnis (misal: cek apakah periode khidmat aktif).
5. Database (Infrastructure): Eksekusi Prisma Query.
6. Revalidation: Panggil `revalidatePath()` atau `revalidateTag()` agar UI terupdate.

**Contoh Implementasi Server Action**

```typescipt
'use server'

import { z } from 'zod'
import { revalidatePath } from 'next/cache'
import { getSession } from '@/lib/auth'
import { createLaporanAction } from '@/modules/wajib-khidmah/application'
import { laporanSchema } from '@/modules/wajib-khidmah/domain'

export async function submitLaporan(formData: FormData) {
  // 1. Validasi Zod
  const parsed = laporanSchema.safeParse(Object.fromEntries(formData))
  if (!parsed.success) return { success: false, errors: parsed.error.flatten() }

  // 2. Auth Check (via Better Auth helper)
  const session = await getSession()
  if (!session) return { success: false, error: 'Unauthorized' }

  // 3. Business Logic & DB
  const result = await createLaporanAction(parsed.data, session.user.id)
  
  // 4. Revalidate
  revalidatePath('/dashboard/wajib-khidmah/laporan')
  
  return { success: true, data: result }
}
```

### 6. Keamanan & Performa

### A. Keamanan (Security)

- **SQL Injection**: Otomatis ditangani oleh Prisma. DILARANG menggunakan `$queryRaw` dengan string concatenation.
- **File Upload**: Validasi MIME type dan ukuran di server. Simpan di Cloud Storage (R2/S3), JANGAN di folder `/public`.
- **Environment Variables**: Variabel sensitif (DB URL, Secret Keys) TIDAK BOLEH diawali `NEXT_PUBLIC_`.
- **MFA**: WAJIB untuk role `OWNER`, `ADMIN_SEKRETARIAT`, dan `ADMIN_BIDANG_*`.

### B. Performa (Next.js 16 Caching)

Gunakan fitur **Cache Components** untuk data yang jarang berubah (Master Data, Jadwal Falak):

```typescript
export async function getJadwalFalakHarian() {
  'use cache'
  cacheLife('hours')
  cacheTag('falak-jadwal')
  
  // Query Prisma...
}
```

### 7. Next.js 16 Breaking Changes

### A. Async Request APIs (WAJIB)

Semua `params`, `searchParams`, `cookies()`, dan `headers()` adalah Promise. WAJIB di-`await`:

```typescript
// ✅ BENAR
export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params
  const cookieStore = await cookies()
  // ...
}
```

### B. React Compiler Aktif

- **JANGAN** tulis `useMemo`, `useCallback`, `memo()` manual.
- React Compiler sudah otomatis melakukan memoization.

---

### C. Server Actions First

- Gunakan `'use server'` untuk mutasi data.
- REST API (`/api/`) hanya untuk webhook/publik.

### 8. Larangan Keras

- ❌ DILARANG pakai `pages/` directory.
- ❌ DILARANG buat `tailwind.config.ts` (Tailwind v4 = CSS-first).
- ❌ DILARANG tulis `useMemo`/`useCallback` manual (React Compiler).
- ❌ DILARANG pakai `unstable_cache` (pakai Cache Components).
- ❌ DILARANG hardcode role/levelCode (ambil dari DB/enum).
- ❌ DILARANG generate nomor surat sebelum status `SENT`.
- ❌ DILARANG buat auto-notif WA/Email di MVP (manual dulu).
- ❌ DILARANG pakai `any` type (TypeScript strict mode).
- ❌ DILARANG import dari `@prisma/client` langsung (gunakan `@/generated/client`).
- ❌ DILARANG user PW/PC mengakses data organisasi lain.
