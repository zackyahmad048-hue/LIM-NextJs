## 1. Tujuan

Dokumen ini mengatur standar penulisan Server Actions, API Routes, dan format respons di Platform LIM untuk memastikan konsistensi, keamanan, dan kemudahan pemeliharaan kode. Setiap developer dan AI Agent WAJIB mematuhi konvensi ini saat menulis endpoint atau mutasi data.

## 2. Server Actions vs API Routes

### 2.1 Kapan Menggunakan Masing-Masing

| Kebutuhan | Gunakan | Lokasi File |
|-----------|---------|-------------|
| Mutasi data dari form UI | Server Action (`'use server'`) | `src/modules/<domain>/presentation/actions/` |
| Query data untuk UI | Server Component / Queries | `src/modules/<domain>/presentation/queries/` |
| Endpoint publik (tanpa login) | API Route (`/api/...`) | `src/app/api/<domain>/...` |
| Webhook / Integrasi eksternal | API Route | `src/app/api/webhooks/...` |
| Mobile client / Third-party | API Route + Bearer Token | `src/app/api/v1/...` |

### 2.2 Aturan Dasar
- **Default**: Gunakan Server Actions untuk semua mutasi internal.
- **API Routes** hanya untuk kasus khusus: publik, webhook, mobile, integrasi.
- **DILARANG** menggunakan `fetch('/api/...')` dari client untuk mutasi internal.

### 2.3 Struktur Folder


### 3. Format Respons Server Actions (WAJIB)

Semua Server Actions **WAJIB** mengembalikan objek dengan tipe `ActionResult<T>` yang konsisten:

```typescript
// src/types/api.ts
export type ActionResult<T> = {
  success: boolean;
  data?: T;
  error?: string;
  errors?: Record<string, string[]>; // Dari Zod flatten
};
```

### 3.2 Contoh Implementasi

```typescript
'use server'

import { z } from 'zod'
import { revalidatePath } from 'next/cache'
import { getSession } from '@/lib/auth'
import { createLetterAction } from '@/modules/letter/application'
import { letterSchema } from '@/modules/letter/domain'
import type { ActionResult } from '@/types/api'
import type { Letter } from '@/generated/client'

export async function submitLetter(
  formData: FormData
): Promise<ActionResult<Letter>> {
  // 1. Validasi Zod
  const parsed = letterSchema.safeParse(Object.fromEntries(formData))
  if (!parsed.success) {
    return { 
      success: false, 
      errors: parsed.error.flatten().fieldErrors 
    }
  }

  // 2. Auth Check
  const session = await getSession()
  if (!session) {
    return { success: false, error: 'Unauthorized' }
  }

  // 3. Authorization Check (RBAC)
  const allowedRoles = ['OWNER', 'ADMIN_SEKRETARIAT']
  if (!allowedRoles.includes(session.user.role)) {
    return { success: false, error: 'Forbidden: Insufficient permissions' }
  }

  // 4. Business Logic & DB
  try {
    const result = await createLetterAction(parsed.data, session.user.id)
    
    // 5. Revalidation
    revalidatePath('/dashboard/letters')
    
    return { success: true, data: result }
  } catch (error) {
    console.error('[submitLetter]', error)
    return { success: false, error: 'Gagal menyimpan surat' }
  }
}
```

### 3.3 Aturan Server Actions

- **WAJIB** return `ActionResult<T>`, tidak boleh return data mentah.
- **WAJIB** validasi input dengan Zod di awal.
- **WAJIB** cek session dan otorisasi di dalam action.
- **WAJIB** panggil `revalidatePath()` atau `revalidateTag()` setelah mutasi sukses.
- **WAJIB** handle error dengan `try/catch` dan log error ke console.
- **DILARANG** throw error ke client (selalu return `ActionResult`).

### 4. Format API Route (REST)

### 4.1 Success Response

```json
{
  "success": true,
  "data": {
    "id": "cuid123",
    "nomorSurat": "001/PP/H/XI/2026",
    "perihal": "Surat Tugas Guru Bantu"
  },
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 100,
    "totalPages": 5
  }
}
```

### 4.2 Error Response

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Data yang dikirim tidak valid",
    "details": [
      { "path": "namaLembaga", "message": "Nama lembaga minimal 3 karakter" },
      { "path": "email", "message": "Format email tidak valid" }
    ]
  }
}
```
### 4.3 HTTP Status Codes

| Code    | Arti                  | Kapan Digunakan                         |
| ------- | --------------------- | --------------------------------------- |
| `200` | OK                    | GET sukses, PUT/PATCH sukses            |
| `201` | Created               | POST sukses (resource baru dibuat)      |
| `204` | No Content            | DELETE sukses                           |
| `400` | Bad Request           | Validasi gagal (Zod error)              |
| `401` | Unauthorized          | Tidak login / token expired             |
| `403` | Forbidden             | Login tapi tidak punya akses            |
| `404` | Not Found             | Resource tidak ditemukan                |
| `409` | Conflict              | Duplikasi data (misal: email sudah ada) |
| `422` | Unprocessable Entity  | Validasi bisnis gagal                   |
| `429` | Too Many Requests     | Rate limit exceeded                     |
| `500` | Internal Server Error | Error server tak terduga                |

### 4.4 Contoh Implementasi API Route

```typescript
// src/app/api/v1/letters/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { getSession } from '@/lib/auth'
import { listLettersQuery } from '@/modules/letter/presentation/queries'
import { letterFilterSchema } from '@/modules/letter/domain'

export async function GET(request: NextRequest) {
  try {
    // 1. Auth Check
    const session = await getSession()
    if (!session) {
      return NextResponse.json(
        { success: false, error: { code: 'UNAUTHORIZED', message: 'Login required' } },
        { status: 401 }
      )
    }

    // 2. Parse Query Params
    const searchParams = request.nextUrl.searchParams
    const parsed = letterFilterSchema.safeParse({
      page: searchParams.get('page'),
      limit: searchParams.get('limit'),
      status: searchParams.get('status'),
    })

    if (!parsed.success) {
      return NextResponse.json(
        { 
          success: false, 
          error: { 
            code: 'VALIDATION_ERROR', 
            message: 'Invalid query parameters',
            details: parsed.error.flatten().fieldErrors 
          } 
        },
        { status: 400 }
      )
    }

    // 3. Fetch Data
    const result = await listLettersQuery(parsed.data, session.user)

    return NextResponse.json({
      success: true,
      data: result.items,
      meta: {
        page: result.page,
        limit: result.limit,
        total: result.total,
        totalPages: result.totalPages,
      }
    })
  } catch (error) {
    console.error('[GET /api/v1/letters]', error)
    return NextResponse.json(
      { success: false, error: { code: 'INTERNAL_ERROR', message: 'Server error' } },
      { status: 500 }
    )
  }
}
```

### 5. Next.js 16 Async Request APIs (WAJIB)

### 5.1 Breaking Change Penting

Di Next.js 16, semua `params`, `searchParams`, `cookies()`, dan `headers()` adalah **Promise**. WAJIB di-`await`.

### 5.2 Contoh Benar vs Salah

```typescript
// ❌ SALAH (Next.js 14/15 style — akan error di Next.js 16)
export default function LetterPage({ params }: { params: { id: string } }) {
  const { id } = params
  const cookie = cookies().get('session')
}

// ✅ BENAR (Next.js 16)
export default async function LetterPage({ 
  params 
}: { 
  params: Promise<{ id: string }> 
}) {
  const { id } = await params
  const cookieStore = await cookies()
  const cookie = cookieStore.get('session')
}
```

### 5.3 Route Handler

```typescript
// ✅ BENAR
export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params
  const searchParams = new URL(request.url).searchParams
  const cookieStore = await cookies()
  const headersList = await headers()
  
  // ... logic
}
```

### 5.4 Server Action dengan Params

```typescript
'use server'

export async function deleteLetter(
  id: string,
  formData: FormData
) {
  const session = await getSession()
  const headersList = await headers()
  const ipAddress = headersList.get('x-forwarded-for')
  
  // ... logic
}
```

### 6. Pagination Convention

### 6.1 Query Params Standar

| Param     | Default | Max | Deskripsi                    |
| --------- | ------- | --- | ---------------------------- |
| `page`  | 1       | \-  | Nomor halaman (mulai dari 1) |
| `limit` | 20      | 100 | Jumlah item per halaman      |

### 6.2 Helper Function

```typescript
// src/lib/pagination.ts
export function parsePagination(searchParams: URLSearchParams) {
  const page = Math.max(1, parseInt(searchParams.get('page') || '1'))
  const limit = Math.min(100, Math.max(1, parseInt(searchParams.get('limit') || '20')))
  const skip = (page - 1) * limit
  
  return { page, limit, skip }
}

export function buildPaginationMeta(page: number, limit: number, total: number) {
  return {
    page,
    limit,
    total,
    totalPages: Math.ceil(total / limit),
    hasNextPage: page * limit < total,
    hasPrevPage: page > 1,
  }
}
```

### 6.3 Contoh Penggunaan

```typescript
// Di query function
export async function listLettersQuery(
  filter: LetterFilter,
  user: SessionUser
) {
  const { page, limit, skip } = parsePagination(filter.searchParams)
  
  const [items, total] = await Promise.all([
    prisma.letter.findMany({
      where: buildLetterWhere(filter, user),
      skip,
      take: limit,
      orderBy: { createdAt: 'desc' },
    }),
    prisma.letter.count({ where: buildLetterWhere(filter, user) }),
  ])

  return {
    items,
    page,
    limit,
    total,
    totalPages: Math.ceil(total / limit),
  }
}
```

```typescript
import { z } from 'zod'

export const letterFilterSchema = z.object({
  page: z.coerce.number().int().positive().default(1),
```

### 8. Revalidation Strategy

### 8.1 Next.js 16 Cache Components

Gunakan `'use cache'` untuk data yang jarang berubah:

```typescript
// src/modules/falak/presentation/queries/get-jadwal.query.ts
export async function getJadwalFalakHarian(tanggal: Date) {
  'use cache'
  cacheLife('hours')
  cacheTag('falak-jadwal')
  
  const jadwal = await prisma.jadwalShalat.findUnique({
    where: { tanggal }
  })
  
  return jadwal
}
```

### 8.2 Revalidation Setelah Mutasi

```typescript
'use server'

import { revalidatePath, revalidateTag } from 'next/cache'

export async function updateLetter(id: string, formData: FormData) {
  // ... logic update
  
  // Path-based: untuk halaman spesifik
  revalidatePath('/dashboard/letters')
  revalidatePath(`/dashboard/letters/${id}`)
  
  // Tag-based: untuk data yang dipakai di banyak tempat
  revalidateTag('letters-list')
  revalidateTag(`letter-${id}`)
  
  return { success: true, data: result }
}
```
### 8.3 Konvensi Tag Naming

| Tag                          | Kegunaan                 |
| ---------------------------- | ------------------------ |
| `letters-list`             | Daftar semua surat       |
| `letter-{id}`              | Detail surat spesifik    |
| `falak-jadwal`             | Jadwal shalat            |
| `wk-laporan-{penugasanId}` | Laporan WK per penugasan |
| `user-{id}`                | Data user spesifik       |

### 9. Error Handling Pattern

### 9.1 Pattern Standar

```typescript
'use server'

import { Prisma } from '@/generated/client'
import { z } from 'zod'

export async function someAction(input: unknown) {
  try {
    // 1. Validasi
    const parsed = schema.safeParse(input)
    if (!parsed.success) {
      return { success: false, errors: parsed.error.flatten().fieldErrors }
    }

    // 2. Auth & Authorization
    const session = await getSession()
    if (!session) return { success: false, error: 'Unauthorized' }
    
    // 3. Business Logic
    const result = await doSomething(parsed.data)
    revalidatePath('/path')
    
    return { success: true, data: result }
  } catch (error) {
    // 4. Error Classification
    console.error('[someAction]', error)
    
    if (error instanceof z.ZodError) {
      return { success: false, errors: error.flatten().fieldErrors }
    }
    
    if (error instanceof Prisma.PrismaClientKnownRequestError) {
      // P2002: Unique constraint violation
      if (error.code === 'P2002') {
        return { success: false, error: 'Data sudah ada' }
      }
      // P2025: Record not found
      if (error.code === 'P2025') {
        return { success: false, error: 'Data tidak ditemukan' }
      }
      return { success: false, error: 'Database error' }
    }
    
    // 5. Generic Error (jangan expose detail ke client)
    return { success: false, error: 'Terjadi kesalahan pada server' }
  }
}
```

### 10. Rate Limiting

### 10.1 Aturan Rate Limit

| Endpoint                          | Limit    | Window             |
| --------------------------------- | -------- | ------------------ |
| API Publik (falak, verifikasi QR) | 100 req  | per menit per IP   |
| API Auth (login, register)        | 10 req   | per menit per IP   |
| API Internal (butuh auth)         | 1000 req | per menit per user |
| File Upload                       | 20 req   | per menit per user |

### 10.2 Implementasi dengan Upstash Redis

```typescript
// src/lib/rate-limit.ts
import { Ratelimit } from '@upstash/ratelimit'
import { Redis } from '@upstash/redis'

const ratelimit = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(100, '1 m'),
  analytics: true,
})

export async function checkRateLimit(identifier: string) {
  const { success, limit, remaining, reset } = await ratelimit.limit(identifier)
  
  return {
    success,
    limit,
    remaining,
    reset,
  }
}
```

### 10.3 Penggunaan di API Route

```typescript
export async function GET(request: Request) {
  const ip = request.headers.get('x-forwarded-for') || 'anonymous'

    return NextResponse.json(
      { success: false, error: { code: 'RATE_LIMIT', message: 'Too many requests' } },
      { status: 429 }
    )
  }
  
  // ... logic
```

### 12. File Upload API

### 12.1 Multipart Form Data

```typescript
'use server'

import { uploadToR2 } from '@/lib/storage'

export async function uploadFile(
  formData: FormData
): Promise<ActionResult<{ url: string }>> {
  const session = await getSession()
  if (!session) return { success: false, error: 'Unauthorized' }

  const file = formData.get('file') as File
  if (!file) return { success: false, error: 'File tidak ditemukan' }

  // Validasi
  const ALLOWED_TYPES = ['application/pdf', 'image/jpeg', 'image/png']
  const MAX_SIZE = 5 * 1024 * 1024 // 5MB

  if (!ALLOWED_TYPES.includes(file.type)) {
    return { success: false, error: 'Tipe file tidak diizinkan' }
  }
  if (file.size > MAX_SIZE) {
    return { success: false, error: 'Ukuran file melebihi 5MB' }
  }

  try {
    // Generate nama acak
    const ext = file.name.split('.').pop()
    const filename = `${crypto.randomUUID()}.${ext}`
    
    // Upload ke R2
    const url = await uploadToR2(file, filename)
    
    revalidateTag('uploads')
    return { success: true, data: { url } }
  } catch (error) {
    console.error('[uploadFile]', error)
    return { success: false, error: 'Gagal mengupload file' }
  }
}
```

### 13. Larangan Keras

- ❌ DILARANG return data mentah dari Server Actions (selalu bungkus ActionResult<T>).
- ❌ DILARANG throw error ke client dari Server Actions.
- ❌ DILARANG bypass validasi Zod di Server Actions.
- ❌ DILARANG menggunakan fetch('/api/...') dari client untuk mutasi internal.
- ❌ DILARANG hardcode HTTP status code (gunakan konstanta).
- ❌ DILARANG expose stack trace atau detail error internal ke client.
- ❌ DILARANG menggunakan unstable_cache (gunakan Cache Components).
- ❌ DILARANG lupa await pada params, searchParams, cookies(), headers() di Next.js 16.
- ❌ DILARANG membuat API Route untuk mutasi internal (gunakan Server Actions).
- ❌ DILARANG menyimpan file upload di folder /public atau /uploads server.
- ❌ DILARANG lupa revalidatePath() atau revalidateTag() setelah mutasi.
- ❌ DILARANG menggunakan any type untuk response API.
