## 1. Purpose

Dokumen ini mendefinisikan standar database dan penulisan schema Prisma yang digunakan oleh LIM Digital Platform. Dokumen ini menjadi acuan mutlak dalam perancangan schema, relasi antar domain, migrasi, serta pengelolaan data untuk memastikan konsistensi, keamanan, dan performa.

---

## 2. Database Engine & ORM

- **Database:** PostgreSQL (Neon Serverless)
- **ORM:** Prisma ORM (v6+)
- **Client Output:** `../generated/client` (DILARANG import langsung dari `@prisma/client`)

---

## 3. Database Principles

Seluruh perancangan database mengikuti prinsip berikut:
- **Single Source of Truth:** Satu definisi schema untuk seluruh aplikasi.
- **Normalisasi Data:** Menghindari redundansi, memisahkan entitas yang berbeda.
- **Referential Integrity:** Menggunakan Foreign Key dan constraint database secara ketat.
- **Audit Ready:** Setiap entitas bisnis mutable wajib memiliki jejak audit.
- **Migration Based:** Perubahan schema produksi HANYA melalui Prisma Migration.

---

## 4. Naming Convention

### Model / Table
Menggunakan `PascalCase` (Prisma convention).  
Contoh: `LaporanMingguan`, `LetterNumberCounter`, `PenugasanStruktural`.

### Column / Field
Menggunakan `camelCase`.  
Contoh: `namaLengkap`, `tanggalLapor`, `isActive`, `deletedAt`.

### Enum & Enum Values
Menggunakan `UPPER_SNAKE_CASE`. Setiap value **WAJIB** di baris terpisah (DILARANG inline).  
Contoh: 
```prisma
enum LetterStatus {
  DIKETIK
  REVIEW
  APPROVED
  SENT
  ARCHIVED
}
```
### Primary Key
Seluruh tabel menggunakan field `id` dengan tipe `String` dan default `cuid()`.
Contoh: `id String @id @default(cuid())`

### Foreign Key
enamaan mengikuti format: `[namaModel]Id` (camelCase).
Contoh: `userId`, `lembagaId`, `penugasanId`.

---

### 5. Common Columns
---
Seluruh model WAJIB memiliki minimal:
```prisma

id        String   @id @default(cuid())
createdAt DateTime @default(now())
updatedAt DateTime @updatedAt
```
Untuk entitas bisnis mutable, **WAJIB** menambahkan:

```prisma
createdById String?
updatedById String?
deletedAt   DateTime? // Untuk Soft Delete
```
---

### 6. Soft Delete vs Hard Delete

### Soft Delete (`deletedAt`)

Wajib diterapkan pada entitas bisnis mutable yang membutuhkan riwayat dan audit trail:

- `Letter` (Surat tidak pernah benar-benar hilang)
- `User` (Akun dinonaktifkan, bukan dihapus)
- `Penugasan` (Riwayat penugasan tetap ada untuk evaluasi)

### Hard Delete (`onDelete: Cascade`)

Diterapkan pada tabel join, lookup, reference, atau data anak yang tidak punya nilai historis independen:

- `DetailKitab` (Hapus otomatis saat LaporanMingguan induk dihapus)
- `PendaftaranEvent` (Hapus otomatis saat webinar dihapus)
- `JurnalHarianSafari` (Hapus otomatis saat delegasi dihapus)

---

### 7. Audit Trail
---

Perubahan penting dicatat melalui field audit atau tabel `AuditLog`.
Tabel AuditLog menyimpan: `userId`, `action`, `entity`, `entityId`, `metadata` (JSON string), `ipAddress`, `createdAt`.

Field `createdById` / `updatedById` wajib ada pada entitas bisnis yang membutuhkan riwayat kepemilikan (misal: `Letter`, `Article`, `LaporanMingguan`).

### 8. Domain Structure
---
Database dibagi berdasarkan domain bisnis (Modular Monolith). Masing-masing domain memiliki tabel sendiri dan hanya berinteraksi melalui relasi yang jelas:

  1. **Authentication**: `User`, `Session`, `Account`
  2. **Kepengurusan**: `PeriodeKhidmat`, `UnitOrganisasi`, `Bidang`, `Jabatan`, `PenugasanStruktural`, `OrganizationalAccount`
  3. **Wajib Khidmah**: `GuruBantuProfile`, `Lembaga`, `Penugasan`, `LaporanMingguan`, `DetailKitab`, `EvaluasiKasus`, `EvaluasiInduk`, `PermohonanGuruBantu`
  4. **Persuratan**: `LetterPeriod`, `LetterNumberCounter`, `Letter`, `LetterLog`
  5. **Portal & Falak**: `Article`, `ArticleCategory`, `FalakConfig`, `JadwalShalat`, `PenetapanAwalBulan`, `AuditLog`
  6. **Safari & Pesantren**: `TitikSafari`, `DelegasiSafari`, `JurnalHarianSafari`, `ApprovalJurnal`, `LaporanSidak`, `SekolahMitra`, `BankMateri`, `PilihanMateriSekolahan`, `PenugasanPesantren`, `LaporanHarianPengajar`, `LaporanHarianKoordinator`, `UmpanBalikPusat`, `UmpanBalikPeserta`
  7. **Dakwah & Binaan**: `KontenDakwah`, `PendaftaranEvent`, `DaerahBinaan`, `LaporanBulananBinaan`
  ---

  ### 9. Relationship Rules
  ---

  Setiap relasi **WAJIB** memenuhi kriteria berikut:
- Memiliki Foreign Key yang dideklarasikan eksplisit.
- Memiliki sisi sebaliknya *(bidirectional relation)*. Jika Model A punya relasi ke Model B, Model B **WAJIB** punya relasi balik ke Model A.
- Tidak membuat relasi melingkar yang tidak diperlukan.
- **Many-to-Many**: WAJIB menggunakan Explicit Join Table (bukan implicit) agar bisa ditambah field metadata di masa depan.
---

### 10. Data Integrity & Indexing
---

Database wajib menjaga:

  - Tidak ada data yatim *(orphan data)*.
  - Foreign key selalu valid.
  - Nilai unik menggunakan `@@unique`.

**Indexing Strategy (WAJIB)**:
Index digunakan pada:

  - Primary Key (otomatis)
  - Foreign Key (misal: `@@index([penugasanId])`)
  - Field yang sering difilter/dicari (misal: `@@index([email])`, `@@index([status])`, `@@index([periodeTahun`, `periodeMinggu])`)
  - Slug atau Nomor Surat (`@@index([nomorSurat])`)
  ----

  ### 11. Race Condition Prevention
  ---
  Untuk operasi yang melibatkan counter/sequence (Penomoran Surat), **WAJIB** menggunakan Prisma Transaction dengan isolation level tinggi:

  ```typescript
  await prisma.$transaction(async (tx) => {
  const counter = await tx.letterNumberCounter.update({
    where: { periodId_levelCode_categoryCode: { periodId, levelCode, categoryCode } },
    data: { currentSeq: { increment: 1 } },
  });
  return counter.currentSeq;
}, { isolationLevel: 'Serializable' });
```
*Aturan Emas*: Generate nomor surat HANYA saat status berubah ke `SENT`. Reset `currentSeq` per `PeriodeKhidmat`, bukan per tahun kalender.

---

### 12. Organizational Account Pattern (Row-Level Security)
---

Semua model yang dimiliki organisasi (PW/PC/Pondok) WAJIB memiliki mekanisme filter agar user dari satu organisasi tidak bisa melihat data organisasi lain.

implementasi di Server Action:

```typescript
const data = await prisma.laporan.findMany({
  where: { 
    daerahBinaan: {
      picLokal: { organizationalAccount: { unitId: session.user.unitId } }
    }
  }
});
```

untuk akun organizational, form laporan WAJIB memiliki field `namaPengisi` dan `jabatanPengisi` untuk audit trail.

### 13. Migration & Seed
---

**Migration**

Perubahan schema HANYA dilakukan melalui Prisma Migration.
Langkah: `Update Schema` → `Generate Migration` → `Review` → `Deploy`.
Perubahan langsung pada database produksi (manual SQL) **DILARANG KERAS**.

**Seed**

Seeder digunakan untuk data awal (Master Data) dan harus *idempotent* (dapat dijalankan berulang tanpa menghasilkan data ganda):
- Role & Permission
- Periode Khidmat Awal
- Administrator/Owner Awal
- Master Data Falak & Kategori
---

### 14. Security & Performance
---

**Security**
- Koneksi database wajib terenkripsi (`sslmode=require`)
- `DATABASE_URL` disimpan di Environment Variables, DILARANG hardcode di schema.
- Akses database HANYA melalui Prisma Client (DILARANG raw query kecuali untuk kasus spesifik yang divalidasi).

**Performance**
- Query wajib menggunakan index bila diperlukan.
- Menghindari *N+1 Query Problem* dengan memanfaatkan `include` atau `select` di Prisma.
- Menggunakan pagination (`skip` & `take`) untuk data yang besar.

### 15. Strict Rules (Larangan Keras)
---
- ❌ DILARANG menggunakan `$queryRaw` atau `$queryRawUnsafe` dengan string concatenation (`+` atau `${}`).
- ❌ DILARANG import dari `@prisma/client` secara langsung. Gunakan `@/generated/client`.
- ❌ DILARANG menulis enum dalam satu baris (inline).
- ❌ DILARANG membuat relasi one-way tanpa opposite relation field.
- ❌ DILARANG menggunakan implicit many-to-many.
- ❌ DILARANG menghapus field/model tanpa backup data dan migration yang aman.
- ❌ DILARANG menggunakan tipe `any` di TypeScript untuk hasil query Prisma.
